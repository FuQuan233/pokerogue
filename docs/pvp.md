# 异步 PVP

## 玩家流程

- 标题画面选择“队伍挑战”，或者在通关记录中选中记录后按回车。
- 只接受本地经典模式胜利记录。首次上传填写 1 至 20 字昵称，昵称归属账号。
- 每个账号最多同时上传 5 队；重复上传同一条记录会提示，删除上传不删除本地记录。
- 公共列表包含自己与其他玩家的上传，按上传顺序分页，均可挑战。挑战时己方从自己的已上传队伍中选。
- 后端不可用时可使用分享码：选择本地经典通关队伍生成完整分享码；接收方粘贴代码，从自己的本地通关记录选择己方阵容挑战。
- 复制失败时显示可全选的完整分享码，不截断；支持旧版完整 Base64 代码。

## 对战规则与保存

- 当前为单打。等级、个体值、性格、闪光、融合、配招、PP 提升、自定义特性/被动、全局与携带道具都由记录还原。
- 双方恢复全部 HP、PP，清除异常及上一战临时能力变化，从中性场地开始。道具按双方分别归属；自战也会重新映射编号，避免串用。
- 对手启用 SMART 及现有最高级选招、换人策略，不额外加 NPC 努力药、种族值或携带物。
- 人民万岁和五年规划支持两侧；劳动法不触发，火箭队工牌不能捕获 PVP 队伍。金币、经验等闯关收益道具保留记录，但本模式没有对应奖励。
- 胜负回到标题，不发放经验、金币、道具和成就，也不进入下一关；保存退出不会写入或删除原冒险存档。
- 本地通关记录来自客户端，当前不是反作弊排名模式，不承诺其内容经过服务器通关验真。

## 后端交接

现有 API：`https://pokerogueapi.fuquan.moe`，复用它的 Authorization 登录凭证及 MariaDB，不使用公开存档接口，也不改变原存档表。

后端仓库：`https://github.com/FuQuan233/rogueserver`。
PVP 后端已提交到 `master`，提交为 `3f208f611d7f3c0b555a48134979c0d093b8c4f5`。该提交的 Build 和 Publish to GHCR 工作流均已成功。镜像发布不会自动更新正在运行的服务器。

请后端维护者完成：

1. 备份现有后端源码及数据库。确认待部署版本包含上述提交；已更新仓库的部署不需要再应用交接补丁。如线上分支有额外改动，合并增量，不覆盖整仓。
2. 按现有部署配置拉取该提交构建的新镜像。源码部署则使用 Go 1.22 或以上运行 `go test ./...`、`go build .`，或者用现有 Dockerfile 重新构建镜像。
3. 按现有方式更新后端容器/进程；保留原数据库、账号认证和环境配置。启动时通过现有数据库初始化机制创建 `pvpProfiles`、`pvpTeams` 两张表；部署账号需有创建表权限。无需清空、迁移或替换现有玩家存档。
4. 确认反向代理转发 `/pvp/*`，并允许带 Authorization 的 GET、POST；单次请求需允许至少 1.1 MB。
5. 用已登录账号调用 `GET /pvp/mine`，应返回 JSON 的昵称与队伍数组；未登录应返回 401。再验证上传、公共列表、自战和删除。不要把 404 当作“没有队伍”。

网页原有 Deploy Beta 只部署静态前端，不会部署该后端。后端上线前共享列表会报服务未部署，分享码仍可使用。

## 接口

全部接口要求原有账号认证；所有写操作以登录账号 UUID 为所有者，不信任客户端 trainerId。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/pvp/mine` | 本人昵称与最多 5 队摘要 |
| GET | `/pvp/teams?before=<id>` | 所有公开队伍，每页 20 条，含本人 |
| GET | `/pvp/teams/<id>` | 单个队伍完整记录 |
| POST | `/pvp/teams` | `{playerName, runEntry}` 上传，服务端首次登记昵称 |
| POST | `/pvp/teams/<id>/delete` | 仅删除登录账号自己的上传 |

上传采用账号行锁和事务检查 5 队上限及重复记录；保存完整 JSON，避免旧版 Go Pokemon 结构丢失 DIY 字段。记录上限 1 MB，输入校验胜利、经典模式、队伍人数、等级、个体值和道具结构。

自动测试覆盖：完整分享码、旧码、截断码、复制失败、同队自战、融合四槽、两侧道具、HP/PP 复原、真实开战行动、最高 AI、结算和存档隔离；后端覆盖校验、原 JSON 保留、5 队上限事务及删除权限。数据库相关自动测试使用 SQL mock，正式数据库迁移与登录接口联调由后端部署时验证。
